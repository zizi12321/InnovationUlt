# 创世发明 · 基础版与三个扩展

《创世发明：终极版》的双人离线电脑对战网页。支持纯基础版；「往日回声」「文明巨擘」「命运之城」可独立启用、自由组合。原生 HTML、CSS 和 JavaScript 模块，所有数据与素材保存在项目内，可直接部署到 GitHub Pages。无需安装依赖、构建或后端服务。

## 已完成

- 右上角「规则」打开离线图文手册：基础、往日回声、文明巨擘、命运之城、图标速查、组合与进阶六个章节，标注本局已开启扩展。复用实际卡牌图标及关键词浮窗，支持点击解释；展开示意可切换五种状态。阅读时暂停电脑，关闭后继续，示意不改变对局。
- 新游戏独立选择扩展，显示五个扩展的完整名称；「往日回声」「文明巨擘」「命运之城」可用，其余两项标注“尚未实现”并预留开关。
- 基础版与往日回声各 115 张牌、各 5 张特殊成就。牌库默认展示基础版，开启扩展后可切换页签查看对应的时代 1–11 牌库及余量。
- 往日回声的替代抽牌、可见回声、奖分、预示区容量、强制推进及免费条例、因预示执行的额外效果；按五种颜色分别实现卡牌程序。
- 文明巨擘包含 115 张伟人、5 项法令，以及由贝尔·格里尔斯引入的 15 张时代 0 牌；完整支持庇佑、四类业报、淡出、法令和食物图标。牌库页签下显示该扩展的抽牌规则，基础页签不显示。
- 命运之城包含 115 张城市和 5 项特殊成就：新增颜色／展开抽城市，先上后下执行即时图标，搜索、旗帜、喷泉与每回合一次的签署强化。卡面保留六个位置；向左展开也露出下层右上角插图。
- 纯基础双人局需要 6 项成就，加入任一扩展需要 7 项，同时加入两个扩展需要 8 项，三个扩展需要 9 项；重复时代的成就按已拥有数量增加分数门槛。
- 顶部时代 1–11 牌库与实际余量；双方五色面板通过页签切换，默认显示我方。
- 正式双人开局：洗牌、预留时代 1–10 的标准成就、每人两张起始手牌、同时亮牌、按英文牌名决定先手。
- 先手首回合一次行动，随后每回合两次行动；抽牌、融合、条例及统御入口。
- 时代 1–11 全部 115 张基础牌（B001–B115）的条例，包括要求、分享、奖励抽牌、选牌、计分、交换、转移、垫底和移除。
- 七种可见图标计数、标准成就资格、五项特殊成就检查、六成就胜利及尝试抽取时代 12 的分数终局。
- 四种展开、自执行与连锁成就、特殊成就移除与恢复、卡牌即时胜利和淘汰。
- 简单离线电脑策略、本机自动存档，以及选牌中途刷新后继续。
- 行动记录按玩家的行动回合分组，换人时加分隔线，双方各完成一次后显示“第 X 回合结束”。组内无序号，条例中的对方响应保留在发动者的组内，旧存档也支持分组显示。
- 新记录在底部；宽屏日志放在右侧，窄屏放在棋盘下方，支持跳到最新记录。页面回合编号与日志一致，每两位玩家完成行动计为一回合；引擎仍分别记录各玩家的行动次数。
- 完整中文卡牌详情、英文对照、关键词浮窗、原位置标记与按颜色区分的卡面。
- 手牌直接显示全部中文效果；手牌、牌表与下层牌按六个印刷位置显示已有标记，基础牌的两个空位置保持为空。
- 双方总统计与牌堆贡献均使用图标及数量；空牌堆保留相同的统计空间。效果中的资源名称按卡牌颜色显示为图标，详情内仍支持解释浮窗。
- 点击出牌区任意卡牌、“展开对比”或牌堆张数，统一打开该颜色牌堆。详情从上到下依次为置顶牌完整效果、实际叠放形态、逐张查看、展开对比。
- 四种展开支持总量与相对增减对比；鼠标悬停临时预览，点击保留预览，逐张查看区显示被覆盖的标记。预览不改变对局。
- 出牌区逐段显示“要求／条例”及主导图标；发动按钮区分“要求”“条例”“要求＋条例”，仍按卡面顺序一次执行整张牌。
- 红色感叹号提示电脑能够分享条例，或要求无法影响电脑；悬停按钮或打开详情可查看图标对比与原因，提示不阻止发动。也提示可由公开信息确定的要求目标缺失；不预测隐藏牌面、抽牌结果或后续选择。
- 新操作记录保存效果来源、类型、段落和实际执行者，显示卡牌图标与“要求／条例”标签。跳过要求、分享、分享奖励和未产生变化都有明确记录；旧日志缺少来源字段时保留原文。

电脑使用本地启发式策略，可以完成八种内容组合的对局；其余扩展、多人和深度搜索策略尚未接入。实现细节和资料差异见 [规则实现范围](./RULES.md)。

## 开始一局

1. 首次打开网页或点击“新开一局”，分别选择是否启用「往日回声」「文明巨擘」「命运之城」，然后点击“开始新对局”。默认显示我方面板和基础牌库；已有存档会自动恢复。
2. 在“我的手牌”中选择一张作为起始牌。电脑提前作出自己的选择，随后双方同时亮牌。
3. 轮到你时，使用行动栏抽牌；点击手牌下方按钮融合；点击置顶牌下方按钮发动条例。分数和置顶时代满足时，可以打开成就区统御。
4. 条例需要选择时，在上方选择区勾选卡牌并确认。多张牌按点击顺序执行；可以全选时提供“按当前顺序全选”，再确认执行。可选效果允许跳过。
5. 切换“电脑”页签查看敌方公开面板。敌方手牌、计分牌、预示牌只展示牌背时代与所属扩展；电脑行动不会自动切走我方页签。
6. 开启往日回声时，预示牌显示在手牌下方。融合行动后必须选择一张符合时代条件的预示牌推进，接着完成它的免费条例。预示区上限依次为未展开 5、左 4、右 3、上 2、斜向 1；上限降低不弃掉已有预示牌。

文明巨擘的伟人只有业报，不显示条例发动按钮。满足条件时从行动栏打开法令，详情中显示成本与效果；对手持有的法令会被归还公共区，下次才能取得。伟人扩展细节见 [规则实现范围](./RULES.md#文明巨擘)。

命运之城的城市没有条例发动按钮。符合签署条件时，先照常点击另一张牌的发动按钮，再选择置顶城市与要移除的手牌；可选择正常发动。面板总计显示有效旗帜／可见旗帜和喷泉，成就区提供分颜色比较。城市即时图标的中文解释可在手牌和详情直接阅读。

电脑行动时可点“暂停电脑”。打开卡牌详情也会暂缓电脑，关闭后继续。刷新页面会恢复当前浏览器的存档；“新开一局”会先确认再替换进度。浏览器数据属于当前网址，不会跨浏览器或端口同步。

## 本地打开

安装 Node.js 18 或更新版本后，在此目录打开终端，执行：

```sh
node tools/serve.mjs
```

用外部浏览器访问终端显示的 `http://127.0.0.1:4173`。脚本不会自动打开浏览器，按 Ctrl+C 停止。

也可以使用 `npm start`，不需要运行 `npm install`。如果端口被占用：

```sh
node tools/serve.mjs --port=4174
```

不能直接双击 `index.html`：浏览器在 `file://` 下通常限制 JavaScript 模块和 JSON 读取。项目也兼容其他普通静态 HTTP 服务。打开本地网页时无需联网。

## 对局与预览

“当前对局”使用真正的局面与规则。正式开局后，115 张基础牌分布为：牌库 101 张、预留标准成就 10 张、双方起始手牌共 4 张；选择起始牌不会额外消耗牌库。启用往日回声时，另有独立洗牌的 115 张扩展牌和 5 张特殊成就。启用文明巨擘时，另有 115 张伟人和 5 张公共法令；15 张时代 0 牌在对应伟人效果执行前不进入对局。启用命运之城时增加 115 张城市和 5 项特殊成就。

“示例摆牌”和“空白棋盘”仍使用基础牌查看布局。示例牌库剩余 92 张，双方展示 23 张；空白棋盘牌库包含全部 115 张。切换这两种预览不会更改当前对局，点击“当前对局”可以继续。

时代牌堆打开的是该时代完整的公开牌表，既不暴露剩余牌身份，也不暴露牌库顺序。

## 部署到 GitHub Pages

1. 在 GitHub 建立仓库，将本目录中的文件和子目录放到仓库根目录，保证根目录可见 `index.html`。保留 `.nojekyll`。
2. 进入仓库 **Settings → Pages**。
3. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
4. 选择保存文件的分支，例如 `main`，目录选择 **/ (root)**，点击 **Save**。
5. 等待 GitHub 完成部署，访问 Pages 设置中显示的网址。

项目使用相对资源路径，可部署到 `https://用户名.github.io/仓库名/` 这样的仓库子目录。发布后不需要 Node.js 服务器；本项目也不需要自定义构建工作流。具体入口见 [GitHub Pages 官方部署说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

若选择从 `/docs` 发布，应把本目录的内容整体放进仓库的 `docs/`，并把 Pages 目录设为 `/docs`。

## 代码结构与存档

卡牌资料与局面分开。所有区域使用卡牌 ID；牌库及五色牌堆的数组末尾表示置顶，归还牌放回原来所属套组和时代的牌库底部。引擎按启用内容检查 115／230／345／460 张普通牌（引入时代 0 后再加 15 张）在牌库、手牌、面板、计分区、预示区、成就区和移除区之间恰好出现一次，5／10／15 张特殊成就和启用伟人时的 5 项法令另行校验；持续业报的虚拟区域不会复制实体卡牌。

条例按扩展和卡牌颜色在 `src/effects-base-*.js`、`src/effects-echoes-*.js` 中逐张实现，由 `src/effects.js` 汇总注册，不通过解析中文描述推断规则。`src/engine.js` 在条例开始时固定分享和要求的资格以及可见回声；选牌会暂停结算，确认后继续。存档保存行动开始前的状态、行动和已经确认的选择；恢复时重放同一事务，不会重新洗牌或重复消耗行动。

`src/ai.js` 获得自己的手牌、计分牌、预示牌及双方公开信息，不接收牌库顺序、对手隐藏牌正面或标准成就正面。当前只使用启发式策略，不依赖大模型、联网或远程服务。

自执行使用独立的执行层，保留正在处理的效果和选择。自执行中再次触发自执行时，先抽取并统御时代 11 的连锁成就，再继续执行；任何即时终局都会立即停止后续效果。原有 v2 存档仍可读取，新增字段会自动补齐。含业报选牌的存档也沿用行动与答案重放；随机洗牌使用存档内的随机数状态。

数据包含 460 张时代 1–11 牌、15 张时代 0 牌、15 项特殊成就及 5 项法令。无时代的特殊成就和法令继续使用 `-1`，不放入时代牌库。已有完整图鉴仍是另一份独立文件。
